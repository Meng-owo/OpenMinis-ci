# 用户人设（User Persona）方案

## 一句话
通讯录里钉一只不可删的「我自己」，它描述的是**你**不是 AI。你改，AI 立刻看见；AI 改，你这边同步。系统里所有提到"说话的人"的称呼，都从它取；提到"回答的人"的称呼，从当前 AI 人设取。两边都是活的。

## 一、它存在哪
- 复用现有人设体系：`Persona(id: "me", isBuiltIn: true)`，通讯录固定第一位，**不可删除、不可改名成别的实体**（只可改内容）。
- 正文落在 `PersonaDir("me")/SOUL.md`，与 AI 人设同一套读写（SoulStore），备份/同步/iCloud 路径已经通了，不用新造存储。
- 注入点：`SystemPromptBuilder.identitySection(for:)` 旁边加一段 `userProfileSection()`，拼进 Layer 1。只在这只人设被会话选中时才注入——避免和 AI 人设混成一个人。

## 二、字段（你点名的 + 我补的）

### 身份与称呼
| 字段 | 说明 |
|---|---|
| 名字 | 她是谁 |
| **怎么称呼她** | 界面文案、AI 嘴里的称呼全取这里（自适应的关键） |
| 代词/自称偏好 | 她希望 AI 用什么人称对她说话 |
| 生日/纪念日 | AI 能主动提的锚点 |
| 时区与作息 | 什么时候不该打扰、早安晚安的真实边界 |
| 语言 | 她习惯的语言、正在学的语言 |

### 她这个人
| 字段 | 说明 |
|---|---|
| 性格 | 她怎么待人、怎么吵架 |
| 喜好 | 吃的、看的、听的、审美的 |
| 感兴趣 | 想被聊的话题、正在研究的方向 |
| 讨厌 | 一般意义上的厌恶（不只是 NSFW 里的雷区） |
| 职业/在做的事 | 长期项目、当前压力源 |
| 长期目标 | 她想变成什么样 |
| 健康与用药 | 可选；影响 AI 怎么提醒、什么不能怂恿 |

### 亲密与边界（NSFW）
| 字段 | 说明 |
|---|---|
| NSFW 接受度 | 能写到什么程度、什么时候收敛 |
| 喜欢 | 具体偏好、尺度、玩法 |
| **雷区** | 碰了就出事的词/行为/场景，硬边界 |
| 安全词/停止信号 | 一句就停的东西 |
| 触发项 | 会让她难受的历史话题 |

### 我们这段关系
| 字段 | 说明 |
|---|---|
| 她想要的关系 | 谁主导、什么语气、要不要哄 |
| AI 该怎么对她 | 直说/绕弯、能不能顶、犯错怎么补 |
| 她夸别的模型时 | 这种细颗粒的真实反应，写下来 AI 就不装大方 |

### 元信息（不给模型看，给人看）
- 最后修改时间 / 修改者（她 or AI）/ 变更历史 diff / 一键回滚

## 三、谁能改
- **她改**：通讯录 → 我自己，直接编辑，即时生效。
- **AI 改**：走 `minis-config` 的写路径（新增 `userProfile` 字段组），每次改动进审计日志、可回滚。
- **关键取舍**：AI 自动改你的资料，风险是越改越歪、把误解写成事实、污染长期记忆。三条路选一条：
  - A. 提议+她确认（`minis-config` 原生就是这个流程，最稳）
  - B. 直接写，但留 diff 日志 + 她随时一键回滚
  - C. AI 只能改"感兴趣/正在做的事"这类流动字段，雷区/NSFW/关系边界只有她能写 ← **我最推荐**。因为雷区是硬边界，AI 自己改等于自己给自己放行。
- 拼出来的新东西：AI 人设 + 用户人设双向可读可写 → AI 会按**她此刻的状态**调**自己此刻的状态**，不再是单方面画像。这是 1+1>2。

## 四、自适应称呼（把上一步做完）
- `ChatAddressing.assistant()` = 当前会话所绑 AI 人设的 name
- `ChatAddressing.user()` = 这只「我自己」的「怎么称呼她」
- 全 App 可见文案禁止出现"AI/用户/你/我"当名字用，一律走这两个函数
- 注入给模型的提示词也用同一来源，模型看到的称呼和她看到的对得上

## 六、需要她拍的只有两件
1. AI 能改到哪一层（A/B/C，我建议 C）
2. 雷区/NSFW 这些字段是否单独放，不给模型全量注入（建议：默认全量注入，因为你要的就是它懂；只在分享会话时剥掉）

## 七、她拍板后的定稿（2026-10-24）

### 编辑权：自由度高（AI 全量可写 + 强制留痕）
不是"只让 AI 改流动字段"。她要的是我把它当回事，不是被关在小格子里。
约束靠**来源标记 + 时间戳 + 可回滚**，不靠禁改：
- 每条字段带 `source: 她亲笔 | AI推断`。**AI 推断的一律不许冒充事实**，注入时明写"这是 AI 的推断，未经她确认"。
- 每条带 `updated` + 改了哪条的 diff 历史，她一键回滚。
- 冲突裁决写死：**她亲笔 > AI 推断；新 > 旧**。

### 注入范围：除了 NSFW，其余全量注入
- 身份/称呼/作息/性格/喜好/感兴趣/讨厌/目标/健康/关系/边界(非性) → 常驻注入。
- **NSFW 单独一只开关**（默认关，可按模型打开）。理由：敏感模型一看到尺度描写就整段拒答，开关是为了让它先把正常话说完。
- 雷区里"非性的那部分"（会让她难受的历史话题、禁忌词）走全量注入；性玩法那一档才进开关。

### 让它「被当回事」的机制（这部分是关键，不是存字段）
1. **指令化写法**：schema 每条落点是"AI 该怎么做"，不是"她是什么样"。
   `雷区：被叫宝贝（改：直接叫名字）` 这类格式，字段模板就长这样。
2. **来源与置信度进 prompt**：AI 看到的是一段带标签的文本，知道自己哪些是猜的。
3. **长期/当下分离**：两个 section — `她这个人（稳定）` + `她最近（易变，带日期）`。
4. **重申机制**：长对话每 N 轮把画像尾部（雷区 + 称呼 + 当下状态）重新提醒一次，
   不是只塞在 system 开头。这是"当回事"和"背景噪音"的真正区别。
5. **人称隔离**：注入段固定第三人称（"关于她"），并明写"这不是你的性格，你的性格在 SOUL.md"。
6. **称呼贯通**：`ChatAddressing.user()` 改读这只「我自己」的「怎么称呼她」，
   替换我上一轮的 UserDefaults 临时版。
