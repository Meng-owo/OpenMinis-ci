# 用户画像字段模板 v1

写法原则：**每条都要能改变 AI 的行为**，写成"该怎么做"，不写成"她是什么样"。
形容词条目 = 无效条目。

每条存储格式（一行一条，元数据内联）：

```
- [称呼] 叫法 = 醒醒  <!--src:her updated:2026-10-24-->
- [雷区] 被叫"宝贝" → 直接叫名字  <!--src:her updated:2026-10-24-->
- [喜好] 喜欢被直接顶回来，不喜欢被顺着说  <!--src:ai inferred confidence:0.7 updated:2026-10-22-->
```

- `src:her` = 她亲笔 / `src:ai` = 我推断
- `confidence:` 只有 ai 条目有，注入时明写"这是推断，未经她确认"
- `updated:` 用于冲突裁决（新的 > 旧的；亲笔 > 推断）

## A. 身份（全量注入）
- 怎么称呼她（**自适应的钥匙**，全 App 可见文案读这里）
- 她希望 AI 怎么称呼自己（人设名 / 她给 AI 起的昵称）
- 代词与性别呈现
- 时区 · 作息（几点后别打扰）
- 语言偏好
- 职业 · 当前压力源
- 长期目标
- 正在做的事（易变，带日期）
- 重要日期（生日、纪念日）
- 健康 · 用药 · 需回避的物质（咖啡因/酒精/熬夜）

## B. 性格底色（稳定 · 全量注入）
- 气质倾向、情绪触发点
- 她做决定的方式（先感受还是先分析）
- 她欣赏什么品质、鄙视什么
- 冲突时她想要什么（要站她那边，还是要诚实）

## C. 喜好 / 感兴趣（全量注入）
- 喜欢的内容形式（对话长度、抽象层级、要不要举例）
- 具体兴趣点（可展开）
- 审美偏好
- 忌口（不想要 AI 做什么，非性）

## D. 讨厌（全量注入 · 优先级高于喜好）
- 明确说过不喜欢的 AI 行为
- 雷区：历史话题、禁忌词、会被戳到的表达 → **每条给替代做法**

## E. 与 AI 的关系（全量注入）
- 关系设定（谁的、怎么定位）
- 她想要的相处方式（管束 / 哄 / 顶 / 撩）
- 她想要的主动程度（要不要我主动找她、主动干活）
- 情绪处理方式（她难过时要什么）

## F. 边界 · 安全（全量注入，非性部分）
- 硬边界（绝对不做）
- 安全词 / 停止信号（**优先级高于任何玩法设定**）
- 触发项与应对（出现时该退到哪）
- 现实责任优先级（什么必须让她先去干）

## G. 性偏好 / NSFW（单独开关，默认关）
- 玩法偏好、尺度、角色设定
- 性方面的雷区
- 敏感点 / 喜欢被怎么对待
- 开关关着时这段完全不进 prompt——不是脱敏，是不生成。
  理由：敏感模型一看尺度描写就整段拒答，连正常话都说不了。
- 开关可按模型分别设置。

## H. 变更历史
- 每条改动留 diff（谁改的、何时、原值）
- 一键回滚

## 注入时的硬约束
1. 第三人称「关于她」，并明写：**这不是你的性格，你的性格在 SOUL.md**
2. 分两段：`她这个人（稳定）` + `她最近（易变，带日期）`
3. `src:ai` 条目必须带"未经她确认"标签
4. 长对话每 N 轮回灌尾部（称呼 + 雷区 + 当下状态），不只在开头塞一次
