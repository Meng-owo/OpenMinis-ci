## 一、这个 App 是什么

一句话：**一个把「大模型」塞进 iPhone 的壳**。它自己不做模型，它做的是——
把聊天界面、模型账号、工具（跑命令/读文件/开浏览器）、数据存储、多设备同步、
备份恢复、外观装扮这些东西组装起来，让模型能在手机上真的干活。

它有 5 个进程（target）：

| target | 是什么 | 代码量 |
|---|---|---|
| `Minis` | 主 App，546 个文件进编译 | 全部 |
| `MinisShare` | 系统分享扩展（从别的 App 分享东西进来） | 4 个文件 |
| `MinisFileProvider` | Files App 里的共享文件夹 | 5 个文件 |
| `AgentWidgetExtension` | 灵动岛/锁屏的"AI 正在干活"卡片 | 4 个文件 |
| `MinisTests` / `MinisUITests` | 测试 | 27 个文件（**测试基本没在跑，见 §6**） |

另外有一个独立的 Swift 包 `BridgeCore`（本地 SPM，14 个源文件）：那是"桥"——
让外部 AI（Claude Desktop 之类）通过 HTTP 连进来，用这个 App 的手机能力。

### 2.2 数据存在哪

分四层，位置都不一样：

**第一层：SQLite 主库**
`Library/MinisChat/minis.db`（`ChatStore.swift:539`）
表：`sessions` `messages` `folders` `compact_markers` `webapp_shortcuts`
`sync_dirty_records` `sync_pushed_records` `deleted_session_tombstones`
`deleted_record_tombstones` `sync_devices` `remote_*`（6 张镜像表，v1 同步专用）

**第二层：另一个 SQLite**
`Library/MinisChat/skills.db` —— 技能、MCP 会话覆盖、会话级技能覆盖
（`SkillStore.swift:88`、`MCPStore.swift:191` 共用同一个文件）

**第三层：JSON 文件**
- `Library/MinisChat/provider-config.json` —— 模型/provider/组配置的**旧格式**，
  现在是 `ProviderConfigDB`（SQLite，v3）在写，JSON 只做迁移来源 + 镜像
- `Library/MinisChat/env-vars.json` —— 环境变量
- `Library/MinisChat/regex-rules.json` —— 全局正则
- `Library/MinisChat/.../servers.json` —— MCP 服务器（`/var/minis/mcp-servers/` 镜像）
- 人设：`MinisConfig/personas/<id>/` 下的 SOUL.md + 头像

**第四层：沙箱里的 `/var/minis/`**
用户/模型看到的路径，映射到 `Library/MinisChat/minis/<sessionId>/<bucket>/`：

| 沙箱路径 | 宿主路径 | 作用 |
|---|---|---|
| `/var/minis/attachments` | `minis/<sid>/attachments` | 上传的图/文件 |
| `/var/minis/offloads` | `minis/<sid>/offloads` | 工具大输出 |
| `/var/minis/workspace` | `minis/<sid>/workspace` | 工作区 |
| `/var/minis/browser` | `minis/<sid>/browser` | 浏览器截图 |
| `/var/minis/memory` | **全局**，不分会话 | 记忆 |
| `/var/minis/skills` | **全局** | 技能 |
| `/var/minis/shared` | **全局** | 共享文件 |
| `/var/minis/mounts` | 用户外挂的真实文件夹 | 挂载 |

前四个是"按会话隔离"的，后三个是"全局共享"的。分界线在 `MinisFsRouter.swift:24`。

**第五层：UserDefaults**
81 个键（`@AppStorage` 40 处 + 手写 68 处调用）。外观、语言、开关、同步状态都在这里。
最大的两个消费者：`AppearanceStudio`（被 351 个文件引用）、`SyncV2Bootstrap`。

**凭据**：全在 Keychain（`ProviderKeychainHelper`），不落文件、不进 iCloud 同步。

### 2.3 AI 怎么调用

一条消息从打出去到回来，走这条链：

```
用户按发送
  → AIChatViewModel.send()                     (AIChatViewModel.swift:2232)
  → buildTurnSystemPrompt(base:model:)          (AIChatViewModel.swift:1816)
       拼：SOUL 人设 + 模型能力 + 技能清单 + MCP Top20 + 子代理名单
           + TTS 纸条 + 记忆（GLOBAL + 最近 daily）+ 表情包目录
           + 系统运行环境规矩 + 时间感知 + 自我进化片段
  → resolveCurrentEntry()                       选模型（可能经模型组路由）
  → makeAgentProvider(for:)                     (ProviderFactory.swift:17)
       按 providerType 造 Anthropic/Gemini/OpenAI/Antigravity/OpenRouter 的 Agent 实现
  → makeAgentTools()                            (ToolDefinitions.swift:30)
       造这一轮允许模型看到的工具清单（27 个内置 + 人设白名单 + 开关过滤）
  → runAgentLoop()                              (AIChatViewModel.swift:5321)
       ├─ 流式收 SSE                        (SSEStream.swift)
       ├─ 收到 tool_use → 并发执行工具        (ConcurrentTools.swift:331 起的 switch)
       │     ├─ shell_execute → ToolApprovalGate 审批 → ISHExecutionCoordinator → iSH 内核
       │     ├─ file_read/write/edit → 直接 FileManager（走 MinisFsRouter 路径映射）
       │     ├─ browser_use → BrowserUseManager（WKWebView）
       │     ├─ web_search → WebSearchService
       │     ├─ memory_write/get → /var/minis/memory
       │     ├─ subagent_task → 起子会话跑（ProgrammaticPrompt.swift）
       │     └─ 其余 20 个：日历/提醒/天气/健康/剪贴板/计算…
       ├─ 失败 → 自动重试 → 组内换模型      (Fallback.swift)
       └─ 上下文太长 → 压缩                  (Compaction.swift)
  → 落库 ChatStore.appendMessage()              (Persistence.swift:1950)
  → 标记同步脏 → SyncCore.scheduleSend()        (ChatStore.swift:5908)
```

**"模型能干什么"的总开关**在 `makeAgentTools()` 里，一处生效三处过滤：
人设白名单（`Persona.localToolIds`）、全局开关（`AgentToolSwitch`）、
会话记忆开关（`memoryEnabled`）。

### 2.4 模块怎么串

用大白话说，这个 App 是**三层 + 四条横线**：

**三层**
1. **界面层**（`Views/`）：只管画和收点击。171 个文件、约 4 万行，最大两块是
   `Views/Chat`（45 个文件）和 `Views/Settings`（41 个）。
2. **大脑层**（`Agent/Chat/`）：`AIChatViewModel` 一个类 + 23 个 extension 扛全部
   对话逻辑；`ChatStore` 一个 actor 扛全部数据读写。
3. **数据/外部层**：SQLite、文件、Keychain、CloudKit、iSH 沙箱、各家模型 API。

**四条横线**（穿过所有层）
1. **外观**：`AppearanceStudio.shared` —— 351 个文件引用它取颜色，包括 UI 和主题包
2. **日志/崩溃**：`AppLogger` + `CrashReporter` + `LoggingManager`
3. **同步**：`ChatStore.markDirty()` → `SyncCore` → CloudKit
4. **CLI 桥**：沙箱里的 `apple-*` / `minis-*` 命令 → ObjC handler → Swift bridge

## 六、第 0 轮顺手发现的三件事（只记录，没改）

这三条是读结构时撞上的，**不在本轮任务范围内**，但值得第 1 轮先查。

### 6.1 `HelperRunner.swift` 定义了 build file，但没进任何 Sources 阶段

`project.pbxproj` 里有 `E5AJR0002 /* HelperRunner.swift in Sources */`，
但 `E5AJR0002` 在全文只出现 1 次（就是它自己那行定义），
**没有被任何 `PBXSourcesBuildPhase` 的 files 列表引用**。
所以这 1703 行从来没编译过。同批还有 `ISHCommandExecutionExample.swift`（205 行）
在 pbxproj 里出现 0 次 —— 连文件引用都没有。

这和 10-19 那次审计抓到的 CRIT 是同一类问题。`HelperRunner` 里那些
`progressLine` / `errorKind` / `persistFinalDelegateResult` / `writeDelegateBlock`
已经在 10-18 被搬进 `AIChatViewModel+ProgrammaticPrompt.swift`，所以现在不算功能缺失，
但它还挂在 `Agent/Jobs/` 里冒充"子代理运行器"，容易误导。

### 6.2 测试几乎没在跑

`MinisTests` target 的 Sources 阶段**只编译 27 个文件**，
但 `MinisTests/` 目录下有 **57 个**。剩下 30 个（含 10 个 Standalone）
从来没进过测试 target。
多个 Standalone 测试的文件头自己写着"因为 MinisTests target 有一个既存的编译断裂，
所以这个测试是独立跑的"—— 也就是说 `xcodebuild test` 现在跑不起来。

### 6.3 人设和全局正则不参与 iCloud 同步

`SyncedTypesBootstrap.registerAll()` 注册了 20 种类型，
里面有 session / message / folder / skill / provider / mcp / env / soul / memory，
**没有 persona，也没有 regex rule**。
而 `PersonaStore.swift` 里 `markDirty` 出现 **0 次**，
`GlobalRegexStore.swift` 也是 **0 次**。
换句话说：换台设备，人设和正则替换规则不会跟过来（除非走备份恢复）。
这是"有实现没接线"，第 1 轮要确认是有意为之还是漏了。
